# 居中、字号与字体手册

## 1. 样式元数据的真实生效范围

LumeCard 的样式是**卡片级**的，写在 `metadata` 里。不同卡型支持程度不同：

| 卡型 | `hcenter` 水平居中 | `vcenter` 垂直居中 | `fontSize` 字号 | `fontFamily` 字体 |
|---|---|---|---|---|
| `BASIC` | ✅ | ✅ | ✅ | ✅ |
| `REVERSED` | ✅ | ✅ | ✅ | ✅ |
| `RICH_TEXT` | ✅ | ✅ | ❌ | ❌ |
| `CLOZE` | ❌ | ❌ | ✅ | ❌ |
| `MARKDOWN` | ❌ | ❌ | ❌ | ❌ |
| `MULTIPLE_CHOICE` | ❌ | ❌ | ❌ | ❌ |

**写在不支持的卡型上不会报错，但完全没有效果。** 校验器会给出警告。

### 为什么

- 学习页只对 `BASIC`、`REVERSED`、`RICH_TEXT` 读取 `hcenter`/`vcenter`。
- `CLOZE` 的正文用独立渲染逻辑，只接受字号。
- `MARKDOWN` 使用固定排版（正文/标题/段落/列表居中，代码块保持原样），不接受卡片样式。
- `MULTIPLE_CHOICE` 是固定的选项卡片布局，不接受卡片样式。
- `RICH_TEXT` 不支持 `metadata` 的字号/字体；用 `<h2>`/`<h3>`、`<strong>`、`<span style=\"color:...\">` 组织层次，不要依赖精确字号。

## 2. 水平居中（hcenter）

### 适合居中

- 单词、短语、术语、专有名词
- 人名、地名、日期、数字
- 短公式、符号、化学式
- 一句短定义 / 短答案（单行或两行）
- 语言学习中的「词 ↔ 释义」对照
- 希望呈现「卡片正面就是答案主体」的视觉焦点

### 适合左对齐

- 成段解释、因果分析、论证
- 多行答案、编号列表、要点列表
- 代码、命令、路径
- 表格、公式推导
- 长问题（超过两行）
- 需要逐行扫描比对的内容（法律条文、医学定义、参数表）

### 一个必须注意的限制

`hcenter` 是**整张卡**的设置，正反面同时生效，不能只让正面居中。

因此：

- 正面很短、背面很长 → **不要居中**（背面会被拉成居中的长段落，很难读）。
- 正反面都短且对称 → 居中。
- 正反面长度差异大 → 左对齐，或用 `fontSize` 微调。

### 经验阈值

同时满足以下条件时，可以放心 `hcenter: "true"`：

- 正面最长一行 ≤ 约 20 个汉字（或 ≤ 40 个拉丁字符）
- 背面 ≤ 2–3 行，且没有列表/代码
- 正反面都没有明显「左对齐语义」（如步骤编号、代码缩进）

否则保持左对齐。

## 3. 垂直居中（vcenter）

### 作用

让卡片内容在卡片区域中垂直居中，避免短内容孤零零地贴在顶部，视觉更平衡。

### 关键风险：它会关闭滚动

学习页在 `vcenter=true` 时**不再给内容加垂直滚动**。内容超过一屏就会被截断，而且无法滚动查看。

所以：

- `vcenter: "true"` 只用于**确定能放进一屏**的短卡。
- 经验阈值：可见文本 ≤ 约 180 个字符且 ≤ 6 行；手机上再保守一些（≤ 4–5 行）。
- 长解释、长列表、代码、表格、多段 RICH_TEXT → **绝对不要** `vcenter`。
- 正反面只要有一面可能很长，就不要开 `vcenter`（正反面共用同一个设置）。

### 适合 vcenter 的典型

- 单词/释义
- 短公式
- 人名/日期/符号
- 一句话问答

### 不适合

- 「请解释……的原理」这类长答案
- Markdown 表格/代码（本来也不支持）
- RICH_TEXT 列表/多段
- 任何你无法确定长度的内容

## 4. 字号（fontSize）

- 单位是 sp，范围 **12–120**，默认 **16**。
- 只对 `BASIC`、`REVERSED`、`CLOZE` 生效。
- 同样是整卡生效（正反面共用），正面短、背面长时要折中。

建议：

| 内容 | 字号 |
|---|---|
| 长解释、长问答 | 14–16 |
| 普通定义/概念 | 16–18 |
| 短问答、术语 | 18–22 |
| 单词、短公式、符号 | 20–26 |
| 单个字符/极短符号（如「∑」） | 26–32 |
| 超过 32 | 很少有必要；手机端可能溢出 |

不要用大字号去「强调」长文本——那会让内容更难读。

## 5. 字体（fontFamily）

只使用应用内置字体 ID：

| ID | 说明 | 适用 |
|---|---|---|
| `default` | 应用默认字体 | 绝大多数情况（也可以直接省略） |
| `serif` | 衬线体 | 阅读型语言材料、正式文本 |
| `sans-serif` | 无衬线体 | 通用 |
| `monospace` | 等宽体 | 短代码/命令（长代码请用 MARKDOWN） |
| `cursive` | 手写风格 | 仅拉丁字母的短词/艺术性内容 |

规则：

- **不要写 `user_*`**：这是用户设备上导入的字体 ID，换设备/未安装时会回退，破坏一致性。
- 字体只对 `BASIC`/`REVERSED` 生效；`RICH_TEXT` 用 HTML，`CLOZE`/`MARKDOWN`/选择题不支持。
- 同一牌组尽量统一字体；不要一张卡一个字体。

## 6. 按卡型给出的推荐组合

| 场景 | 卡型 | hcenter | vcenter | fontSize | 备注 |
|---|---|---|---|---|---|
| 外语单词 ↔ 释义 | BASIC | ✅ | ✅ | 20–22 | 正反面都短；最经典的居中场景 |
| 术语 + 一句话定义 | BASIC | ✅ | 可选 | 18–20 | 定义 ≤ 2 行才开 vcenter |
| 概念解释（2–5 行） | BASIC | ❌ | ❌ | 16 | 左对齐便于扫读 |
| 长原理/长答案 | BASIC | ❌ | ❌ | 14–16 | 千万别开 vcenter |
| 短公式 | BASIC | ✅ | ✅ | 22–28 | 如 `a² + b² = c²` |
| 带说明的公式 | BASIC | ❌ | ❌ | 16–18 | 说明部分需要左对齐 |
| 历史事件问答 | BASIC | 可选 | 可选 | 16–18 | 看答案长度；短则居中 |
| 句子填空 | CLOZE | — | — | 16 | 只设字号；长句左对齐更自然 |
| 术语填空 | CLOZE | — | — | 18–20 | 只设字号 |
| 辨析选择题 | MULTIPLE_CHOICE | — | — | — | 不设样式 |
| 表格/代码/步骤 | MARKDOWN | — | — | — | 不设样式 |
| 富文本短说明 | RICH_TEXT | ✅ | 可选 | — | 列表/多段不要 hcenter/vcenter |
| 富文本长批注 | RICH_TEXT | ❌ | ❌ | — | 用 HTML 标题/强调组织 |

## 7. 决策流程（每张卡执行一次）

```text
1. 卡型是 BASIC / REVERSED / RICH_TEXT 吗？
   否 → 不要写 hcenter/vcenter；CLOZE 只考虑 fontSize；其余不写样式。

2. 正面和背面都短且对称吗？
   （≤ 2–3 行、无列表/代码、没有左对齐语义）
   是 → hcenter = "true"
   否 → 省略 hcenter（左对齐）

3. 正反面都能轻松放进一屏吗？
   （≤ 约 180 字符、≤ 5–6 行，且不是列表/表格/代码）
   是 → vcenter = "true"
   否 → 省略 vcenter（保留滚动）

4. 需要调整字号吗？
   BASIC/REVERSED/CLOZE → 按第 4 节写 fontSize
   RICH_TEXT → 用 HTML 标题层级/强调，不写 fontSize

5. 需要特殊字体吗？
   仅 BASIC/REVERSED，且只用内置 ID；否则省略。
```

## 8. JSON 写法

```json
"metadata": {
  "hcenter": "true",
  "vcenter": "true",
  "fontSize": "22"
}
```

- 值必须是**字符串**。
- 不需要的键直接省略，不要写 `"hcenter": "false"`（虽然也能解析，但增加噪音）。
- 不要写 `null` 或布尔值。
- 不要写未知键（如 `align`、`textAlign`、`color`）；应用不会识别。

## 9. 牌组级一致性

样式没有牌组级默认值，必须逐卡设置。但一个牌组内部应保持统一风格：

- **词汇/术语牌组**：普通卡统一 `hcenter=true`、短卡 `vcenter=true`、字号 20–22；长解释卡例外（左对齐、16）。
- **概念/原理牌组**：统一左对齐、16；只有极短的「一句话结论」卡可以居中。
- **公式牌组**：纯公式居中、大字号；带推导/说明的左对齐。
- **语言学习牌组**：单词居中；例句/语法讲解左对齐。

如果一个牌组里大量卡片风格跳变，学习者会感到界面「乱」，也会削弱卡片类型的语义。

## 10. 常见错误

| 错误 | 后果 | 修正 |
|---|---|---|
| 长答案开 `vcenter` | 内容被截断且不能滚动 | 去掉 `vcenter` |
| 正面短、背面长仍 `hcenter` | 背面变成居中的长段落，难读 | 改成左对齐 |
| 给 CLOZE 设 `hcenter` | 无效 | 只设 `fontSize` |
| 给 MARKDOWN 设样式 | 无效 | 删掉 metadata |
| 给 RICH_TEXT 设 `fontSize` | 无效 | 用 HTML 标题层级/强调 |
| 用 `user_xxx` 字体 | 换设备回退 | 用内置 ID 或不设 |
| 把字号写成数字 `20` | 反序列化失败或导入异常 | 写字符串 `"20"` |
| 全牌组都用 14 号字 | 手机端阅读吃力 | 普通内容 16，短词 20+ |
| 全牌组都居中 | 长内容难以扫描，视觉单调 | 按内容长短区分 |
