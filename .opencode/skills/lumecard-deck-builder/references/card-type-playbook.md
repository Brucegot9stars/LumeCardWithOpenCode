# 卡型选择与格式手册

## 1. 先理解每种卡型在学习页的真实表现

| 卡型 | 正面显示 | 背面显示 | 支持的样式元数据 | 适合的知识 |
|---|---|---|---|---|
| `BASIC` | `front` 纯文本 | `back` 纯文本 | 居中、字号、字体 | 定义、问答、原理、因果、事实 |
| `REVERSED` | 与 BASIC 完全相同 | 与 BASIC 完全相同 | 居中、字号、字体 | 双向词条（需另建反向卡） |
| `CLOZE` | `front` 中所有挖空变 `____` | 高亮 `front` 中的答案 | 仅字号 | 术语、公式、语法、命令、条文 |
| `MULTIPLE_CHOICE` | 问题 + 可点选选项 | 选项 + 正确项打勾 | 无 | 辨析、分类、易混点 |
| `MARKDOWN` | GFM Markdown | GFM Markdown | 无 | 表格、步骤、代码、推导、速查 |
| `RICH_TEXT` | HTML 富文本 | HTML 富文本 | 居中 | 强调、批注、多段短内容 |

> **关键事实**：`BASIC` / `REVERSED` 是纯文本，写 `**加粗**`、`# 标题`、`| 表格 |` 会原样显示。需要格式就换 `MARKDOWN` 或 `RICH_TEXT`。

---

## 2. BASIC —— 默认首选

**适用**：定义、概念解释、原理、因果、流程中的单点、事实、比较结论、开放问答。

**写法**：

- `front`：一个明确的问题或提示，只问一个点。
- `back`：直接答案 + 必要的一句解释/例子。
- 用 `\n` 分行；不要用 Markdown 语法。

**好例子**：

```json
{
  "type": "BASIC",
  "front": "为什么 TCP 需要三次握手？",
  "back": "为了确认双方的收发能力都正常，并同步初始序列号，避免历史连接请求造成资源浪费。",
  "title": "TCP 三次握手的目的"
}
```

**坏例子**：

- 正面：「TCP 三次握手的过程、作用和缺点是什么？」（三个考点挤一张卡）
- 正面：「TCP 是什么？」背面一段 500 字（不可评分，回忆负担过重）

**拆分原则**：如果背面有 3 个并列要点，通常拆成 3 张卡，或改成 `MARKDOWN` 做「速查卡」——但速查卡不适合作为主要记忆卡。

---

## 3. REVERSED —— 双向词条，但不会自动反向

**重要**：当前版本中 `REVERSED` 的渲染与 `BASIC` 完全相同，**不会自动生成「背面 → 正面」的卡片**。它只是一个类型标记。

因此：

- 只需要一个方向 → 用 `BASIC`。
- 两个方向都值得练 → **建两张卡**，两张内容互换；其中一张可标为 `REVERSED` 便于筛选，但不要指望应用自动生成。
- 只有真正对称、两个方向都常用时才做双向，例如：
  - 外语单词 ↔ 母语释义（但要注意一词多义，答案必须唯一）
  - 国家 ↔ 首都
  - 符号 ↔ 名称
  - 缩写 ↔ 全称
- 不要反向的情况：一个方向是常识、另一方向答案不唯一、反向问题会变得含糊。

**示例（两条独立卡片）**：

```json
[
  {
    "type": "BASIC",
    "front": "ubiquitous",
    "back": "无所不在的；普遍存在的",
    "title": "GRE 词汇 ubiquitous"
  },
  {
    "type": "REVERSED",
    "front": "无所不在的；普遍存在的",
    "back": "ubiquitous",
    "title": "GRE 词汇反向 ubiquitous"
  }
]
```

## 4. CLOZE —— 填空卡（“天空卡”）

**适用**：术语、公式、语法结构、命令、代码关键字、法律条文、诗句、定义中的关键限定词。它强迫学习者在**上下文**中回忆，比孤立问答更接近真实使用。

**格式**：

```text
{{c1::答案}}
{{c1::答案::提示}}
```

- `c1`、`c2` 是挖空编号；学习页会把**所有** `{{cN::...}}` 同时变成 `____`，背面再统一高亮答案。
- 所以多个编号 ≠ 多张卡，而是同一张卡多个空。**默认一张卡只挖 1 个空**；最多 2 个，且两个空应属于同一知识点。
- 提示 `::提示` 目前不会显示在界面上，不要依赖提示传达关键信息。
- **CLOZE 只渲染 `front`**：学习页背面的高亮内容也来自 `front`，`back` 不参与复习显示。因此：
  - 所有上下文和答案都必须放在 `front`。
  - `back` 建议写成去掉标记的完整句子（便于列表/搜索），或直接留空；**不要把补充解释只写在 `back`**。

**好例子**：

```json
{
  "type": "CLOZE",
  "front": "在 Kotlin 中，用 {{c1::suspend}} 关键字标记可以在协程中挂起的函数。",
  "back": "在 Kotlin 中，用 suspend 关键字标记可以在协程中挂起的函数。",
  "title": "Kotlin 挂起函数关键字"
}
```

**坏例子**：

- `front`：「{{c1::TCP}} 是 {{c2::面向连接}} 的 {{c3::可靠}} 传输层协议，使用 {{c4::三次握手}} 建立连接。」（一张卡 4 个空）
- 把解释写在 `back`：「三次握手是为了……」——学习时看不到。
- 挖空过短：「{{c1::的}}」——没有区分度。

**选择挖空对象**：挖「最值得回忆的那一个词」，不要挖冠词、介词、通用动词。

## 5. MULTIPLE_CHOICE —— 辨析与诊断，不用于简单回忆

**适用**：

- 易混概念辨析（TCP vs UDP、方差 vs 标准差）
- 分类判断（下列哪个属于……）
- 常见误解纠正（下列哪项说法错误）
- 需要从多个相似选项中精确区分

**不适用**：单纯的事实回忆。选择题是「再认」，比「回忆」容易，容易制造「我记住了」的错觉。能直接问答的，优先 `BASIC`。

**格式（必须严格遵守）**：

- `front`：只写问题，不写选项，不写 A/B/C，不写「答案：」。
- `back`：**每行一个选项**；正确项以 `+` 开头；错误项不加任何前缀。
- 默认 4 个选项（3–6 个可接受）。
- 默认**只有一个**正确项。应用技术上支持多个 `+`，如果确实要多选，必须在 `front` 明确写「（多选）」。
- 不要写选项字母/数字前缀（`A)`、`1.`），应用会原样显示。
- 不要在 `back` 里写解释——每一行都会被当成选项。需要解释就另建一张 `BASIC` 卡。

**好例子**：

```json
{
  "type": "MULTIPLE_CHOICE",
  "front": "下列哪一项是 TCP 有而 UDP 没有的特性？",
  "back": "+面向连接\n无连接\n不保证顺序\n头部开销小",
  "title": "TCP 与 UDP 的连接特性"
}
```

**多选例子**：

```json
{
  "type": "MULTIPLE_CHOICE",
  "front": "以下哪些属于 HTTP 幂等方法？（多选）",
  "back": "+GET\n+PUT\nPOST\nPATCH",
  "title": "HTTP 幂等方法"
}
```

**坏例子**：

- `back`: `"A) 面向连接\nB) 无连接"` —— 字母前缀会被当作选项内容。
- `back`: `"+面向连接\n无连接\n答案：A"` —— 「答案：A」会变成一个选项。
- `back`: `"面向连接\n+无连接"` —— 正确项没有放在行首（必须以 `+` 开头）。
- 干扰项明显荒谬（「TCP 是一种水果」）—— 没有诊断价值。

**干扰项设计**：与正确答案同类别、同长度、同语气；最好来自学习者常见的错误理解。

## 6. MARKDOWN —— 结构化知识与代码

**适用**：

- 对比表、参数表、速查表
- 分步骤流程、清单
- 代码片段、命令
- 数学公式（`$$...$$` 块级公式）
- 需要标题层级的多段总结

**格式**：标准 GFM。支持标题、粗体/斜体、删除线、列表、任务列表、表格、引用、代码块、链接、`$$数学$$`。

**渲染特点**：

- 正文、标题、段落、列表默认**居中**；代码块保持自身样式（不居中）。
- 样式元数据（`hcenter`/`vcenter`/`fontSize`）对它无效，不要写。
- 不要混用大段 HTML；需要 HTML 富文本时改用 `RICH_TEXT`。
- 代码块用三反引号并标注语言，便于高亮。
- 表格列不要太多（手机端会横向挤压）；优先 3–4 列。

**好例子**：

```json
{
  "type": "MARKDOWN",
  "front": "## 常见时间复杂度\n\n| 复杂度 | 名称 | 典型例子 |\n|---|---|---|\n| O(1) | 常数 | 数组下标访问 |\n| O(log n) | 对数 | 二分查找 |\n| O(n) | 线性 | 遍历数组 |\n| O(n log n) | 线性对数 | 归并排序 |",
  "back": "从低到高：O(1) < O(log n) < O(n) < O(n log n) < O(n²)。",
  "title": "常见时间复杂度对比"
}
```

**坏例子**：

- 用 MARKDOWN 写一个单词（过度格式化）。
- 把整章内容塞进一张 MARKDOWN 卡（无法通过一次评分判断掌握程度）。
- 用 `hcenter` 控制 MARKDOWN 对齐（无效）。

---

## 7. RICH_TEXT —— 需要颜色、强调、批注的短内容

**适用**：

- 需要在句子内部做颜色/加粗/斜体/下划线强调
- 简短的多段注释、带批注的原文
- 用 HTML 列表呈现的短清单
- 语言学习中的重音、词形变化标注

**格式**：**HTML**，不是 Markdown。常用标签：

```html
<p>段落</p>
<strong>加粗</strong> / <b>加粗</b>
<em>斜体</em> / <i>斜体</i>
<u>下划线</u> / <s>删除线</s>
<h2>小标题</h2>
<ul><li>列表项</li></ul>
<ol><li>有序项</li></ol>
<code>行内代码</code>
<span style="color:#C62828">彩色文字</span>
```

**注意**：

- 写 `**加粗**` 不会渲染，会原样显示；必须用 `<strong>`。
- `hcenter`/`vcenter` 生效；`fontSize`/`fontFamily` 不生效，用标题层级和行内强调组织内容，不要依赖精确字号。
- 复杂表格、布局、脚本不要用 RICH_TEXT；表格用 `MARKDOWN`。
- 不要用 `<script>`、`<style>`、`<iframe>`、事件属性（`onclick` 等）。
- 内容要短；长文用 MARKDOWN 更稳。

**好例子**：

```json
{
  "type": "RICH_TEXT",
  "front": "<h3>ser 与 estar</h3><p><strong>ser</strong> 表示<strong>本质、身份、来源</strong>；<strong>estar</strong> 表示<strong>状态、位置</strong>。</p>",
  "back": "<p>例：<i>Soy</i> estudiante.（身份）<br><i>Estoy</i> cansado.（状态）</p>",
  "title": "西班牙语 ser 与 estar 的区别",
  "metadata": { "hcenter": "true" }
}
```

## 8. 选型决策树

按顺序问：

1. **这是需要从相似选项中辨别的知识吗？** → `MULTIPLE_CHOICE`
2. **这是术语/公式/语法/命令，且上下文本身值得读吗？** → `CLOZE`
3. **这是表格、步骤、代码、公式推导或结构化速查吗？** → `MARKDOWN`
4. **需要颜色/强调/批注，且内容很短吗？** → `RICH_TEXT`
5. **以上都不是？** → `BASIC`
6. **两个方向都值得练吗？** → 再建一张反向卡（不要假设自动生成）

## 9. 一个牌组里可以混用卡型吗？

可以，而且应该。按知识特征选型，不要为了统一而强行全部 BASIC。但要注意：

- 同一牌组的**视觉风格**尽量一致：词汇/术语牌组多用居中；解释/流程牌组多用左对齐。
- 同一知识点的不同侧面，不要用不同卡型重复考同一件事。
- 一个牌组里 `MARKDOWN`/`RICH_TEXT` 的「展示卡」不宜过多；它们适合总结和速查，不适合承担主要评分。

## 10. 快速反例清单

| 反例 | 问题 | 改法 |
|---|---|---|
| 一张 BASIC 卡背面列 6 个要点 | 无法判断是否掌握 | 拆成多张，或改 MARKDOWN 速查卡 + 单独评分卡 |
| CLOZE 一张卡挖 5 个空 | 回忆负荷过大 | 每张只挖 1 个空 |
| CLOZE 的解释写在 `back` | 学习页不显示 | 移到 `front` 或另建 BASIC |
| 选择题 `back` 带「答案：」 | 被解析成选项 | 删掉，正确项只用 `+` |
| 选择题干扰项荒谬 | 无诊断价值 | 用常见错误理解做干扰项 |
| BASIC 里写 Markdown | 原样显示符号 | 改 MARKDOWN/RICH_TEXT |
| 用 REVERSED 指望自动反向 | 当前版本不会 | 另建一张反向卡 |
| 长解释开 `vcenter` | 学习页不能滚动，内容被截断 | 去掉 `vcenter` |
| 给 CLOZE 设居中 | 不生效 | 只设 `fontSize` |
