# LumeCard 知识库构建

把用户提供的知识材料转换成 **一份可被 LumeCard「设置 → 数据管理 → 导入」直接读取的 JSON 文件**。产出必须是「知识库 → 牌组 → 卡牌」三层结构，而不是只有卡片的裸列表。

目标是 **最适合学习**，不是把原文机械切碎：一张卡只考一个点，卡型服务于知识特征，排版服务于阅读体验。

> 本 Skill 同时兼容 OpenCode、Claude Code、Codex、CodeBuddy 等支持 `SKILL.md` 的 agent。
> 安装位置、调用方式与常见问题见同目录下的 `USAGE.md`；维护多份副本见仓库 `scripts/sync-skill.mjs`。

## 开始前先读

按顺序阅读（路径相对于本 SKILL.md）：

1. `references/import-format.md` — 导入 JSON 的精确结构、字段、ID/时间戳规则、导入行为。
2. `references/card-type-playbook.md` — 各卡型的适用知识、格式与渲染限制（含易错点）。
3. `references/style-and-centering.md` — 水平/垂直居中、字号、字体的真实生效范围与选择规则。
4. `references/knowledge-design.md` — 知识库/牌组划分、原子化、标签与数量控制。
5. `assets/example.share.json` — 一份通过校验的完整示例，可直接对照。

## 工作流（按顺序执行）

### 1. 通读材料，建立知识地图

- **完整读取**用户给出的所有文档，不要只读开头或摘要。
- 提取标题层级、核心概念、定义、公式、步骤、对比关系、易混点、例子与结论。
- 判断材料类型：概念型 / 语言词汇型 / 操作流程型 / 考证型 / 代码技术型 / 叙事人文型。不同材料的知识粒度不同。
- 若用户没有说明学习目标，默认按「系统掌握该材料」处理，**不要为此追问**。

### 2. 设计知识库与牌组

- **一个知识库 = 一个连贯的学习领域**（通常对应一份文档或一个主题）。
- **牌组 = 章节 / 主题 / 技能模块**，不是「第 1 页、第 2 页」。
- 每个牌组有清晰的 `name` 和一句话 `description`，选择与主题匹配的 `color`、`icon`。
- 牌组规模建议 20–60 张；超过 80 张考虑拆分，超过 150 张必须拆分。
- 章节层级深时可用 `parentId` 建两层牌组，但优先保持扁平，避免过度嵌套。
- 详细规则见 `references/knowledge-design.md`。

### 3. 抽取原子知识并选卡型

一张卡只容纳一个可独立回忆的知识点。按下面的快速表选型，完整规则见 `references/card-type-playbook.md`：

| 知识特征 | 首选卡型 | 关键原因 |
|---|---|---|
| 定义、概念、原理、因果、问答 | `BASIC` | 最通用，正面问、背面答 |
| 术语、公式、语法、命令、条文、关键词 | `CLOZE` | 在上下文里挖空，避免孤立记忆 |
| 易混概念、分类判断、辨析、「下列哪个」 | `MULTIPLE_CHOICE` | 主动区分干扰项，适合诊断误解 |
| 对比表、步骤清单、代码、推导、结构化速查 | `MARKDOWN` | GFM 表格/列表/代码/数学公式 |
| 需要颜色、强调、批注、多段排版的短内容 | `RICH_TEXT` | HTML 富文本 |
| 真正双向可逆且两个方向都值得练 | `BASIC` ×2（或其中一张标 `REVERSED`） | REVERSED 在当前版本不会自动生成反向卡 |

**绝不要手写 `AI_GENERATED`**（保留给应用内 AI 生成流程）。

### 4. 决定居中与字号

先判断卡型是否支持样式（只有部分卡型生效）：

- `BASIC` / `REVERSED`：水平居中、垂直居中、字号、字体全部生效。
- `RICH_TEXT`：水平/垂直居中生效；字号、字体不生效（用标题层级和行内强调组织内容）。
- `CLOZE`：只有字号生效；水平/垂直居中不生效。
- `MARKDOWN` / `MULTIPLE_CHOICE`：样式元数据不生效（Markdown 渲染器本身居中文本，选择题固定布局）。

选择规则速查：

- **短而对称**（单词、术语、人名、日期、短公式、一句短定义，单行或两行）→ `hcenter=true`。
- **成段解释、列表、代码、表格、多行内容** → 不加水平居中（左对齐更易扫描）。
- **内容能轻松放进一屏**（约 ≤6 行 / ≤180 字符）→ 可加 `vcenter=true`。
- **内容可能很长** → **不要** `vcenter`：垂直居中会关闭学习页的滚动，长内容会被截断。
- 字号默认 16；词汇/短术语 20–24；公式 20–28；长解释 14–16；一般不超过 28。
- 字体只用内置 ID：`default`、`serif`、`sans-serif`、`monospace`、`cursive`；不要写 `user_*`（绑定用户设备）。
- 同一牌组保持风格一致：词汇牌组整体居中，解释型牌组整体左对齐。

完整决策树与 JSON 写法见 `references/style-and-centering.md`。

### 5. 生成导入 JSON

- 顶层使用 **share 格式**：`exportType: "share"`、`version: "1.0.0"`、`schemaVersion: 1`、`exportDate`。
- ID 使用稳定、全局唯一、ASCII 的命名空间，例如：
  - 知识库：`lcg_spanish_basics_kb`
  - 牌组：`lcg_spanish_basics_d01`
  - 卡牌：`lcg_spanish_basics_d01_c001`
- 同一主题重新生成时保持 ID 不变，可覆盖更新而不是产生重复；若旧卡已被学习过或内容大改，换命名空间（如 `_v2`），避免旧学习状态对应新内容。
- 时间戳用 UTC ISO-8601，例如 `2026-11-03T08:00:00.000Z`；同一批可共用一个时间。
- `metadata` 的值必须是字符串：`"hcenter": "true"`、`"fontSize": "20"`。
- 卡牌 `title` 必填且简短（中文约 4–16 字），不要直接复制问题。
- 默认输出到当前工作目录下的 `lumecard-exports/<主题-slug>.lumecard.json`（目录不存在则创建）；用户指定路径则从其。若同名文件已存在，先确认或加版本后缀，不要静默覆盖。
- 字段精确说明见 `references/import-format.md`，可复制 `assets/example.share.json` 后替换内容。

### 6. 运行校验（必做）

```bash
node "<本 skill 目录>/scripts/validate.mjs" "<生成的 json 路径>"
```

- 必须做到 **0 个 ERROR**；WARNING 逐条判断，能改就改。
- 若环境没有 Node，按 SKILL.md 末尾的自检清单人工检查。
- 校验器会检查：结构、引用完整性、重复 ID、卡型格式、Cloze 标记、选择题选项、HTML/Markdown 语法、居中是否对卡型生效、长内容误用垂直居中等。
- 修复后重新运行，直到通过。

### 7. 交付

回复用户时给出：

1. 输出文件的完整路径。
2. 结构摘要：知识库名、牌组数、卡片数、各卡型数量。
3. 设计说明：为什么这样分牌组、为什么选这些卡型/居中方式（2–4 句）。
4. 导入步骤：打开 LumeCard → 设置 → 数据管理 → 导入 → 选择该 JSON。
5. 可选：一张「牌组 → 卡型 → 示例卡」的简表，方便用户快速抽查。

不要粘贴整份 JSON；文件已经落盘时只给路径和摘要。

## 质量红线

- **不生成**：是/否题、答案不唯一的问题、需要图片才能理解的卡、把 5 个以上条目塞进一张卡、与原文无法对应的臆造内容。
- **不重复**：同义反复或只换措辞的卡片只保留一张。
- **不悬空**：每张卡脱离原文也能读懂；代词要还原为具体名词。
- **不超载**：一张卡一个考点；CLOZE 一张卡只挖 1 个空（最多 2 个）。
- **不乱码**：代码、API、命令、公式、专有名词保留原文写法，不要翻译。
- **不牺牲覆盖换数量**：宁可 30 张高质量卡，也不要 100 张复读卡。
- **保持语言一致**：解释使用材料/用户的语言；被学习的语言本身保留原语言。

## 人工自检清单（无 Node 时）

- [ ] JSON 可解析；`knowledgeBases`、`decks`、`cards` 都是数组。
- [ ] 所有 `deck.knowledgeBaseId`、`card.deckId` 都能找到对应实体。
- [ ] 所有 `id` 在各自实体内唯一；时间戳是合法 ISO-8601。
- [ ] 卡型只用 `BASIC`、`REVERSED`、`CLOZE`、`MULTIPLE_CHOICE`、`MARKDOWN`、`RICH_TEXT`。
- [ ] CLOZE 的 `front` 含 `{{c1::答案}}`，`back` 不承载额外解释。
- [ ] 选择题 `back` 每行一个选项，正确项以 `+` 开头，没有 A/B/C 前缀。
- [ ] 只有 BASIC/REVERSED/RICH_TEXT 设置了居中；长内容没有开 `vcenter`。
- [ ] 每个牌组都有卡片；每个知识库都有牌组。
- [ ] 标题简短；标签 1–4 个且风格统一。
