# P0：数据安全修复

本阶段只处理数据库、备份和媒体同步的数据安全问题，不调整复习算法公式、页面生命周期或整体 Gradle/Android 架构。

## 已实施

- 桌面数据库只有在没有用户表/视图且 `user_version=0` 时才初始化。已有库缺表、缺列、版本过新或迁移失败时保留数据并停止启动，不自动删表重建。
- 创建和迁移均使用事务。历史上“列已添加但版本号未更新”的库通过仅针对已知迁移的幂等回退处理；未知迁移不猜测执行。
- 桌面 SQLite 通过连接属性开启外键，Android 通过 `onConfigure` 开启外键，不再在强制下行期间关闭约束。
- `BackupRestoreService` 在同一事务中执行全量替换或合并恢复，包括实体、复习日志、学习计划、算法状态、搜索索引与适用的语录设置。配置覆盖也使用事务。
- 数据恢复前校验文件类型、支持版本、重复 ID、外键引用、卡组父链、时间戳、枚举与算法状态 JSON。分享文件和增量包不能作为全量备份覆盖数据库。
- 新快照包含软删除记录和算法状态，并在一个读事务内取得所有数据，避免各 Repository 分别读取造成快照混杂。
- 上传先读取旧媒体清单，再上传差异文件，最后发布清单；保留云端独有文件。下行只下载缺失或不同的文件，不改写云端媒体清单。
- 媒体传输检查大小与 SHA-1，拒绝路径穿越；本地落盘使用临时文件替换，并检查路径不能通过符号链接逃出媒体根目录。
- 媒体目录统一使用平台已有的 `getMediaBasePath()`，不再把 Android 的应用目录误当作桌面目录。
- 覆盖前的云端备份只将 HTTP 404 视为“无旧数据”。鉴权失败、网络失败、服务器错误及本地写入/读回验证失败会中止覆盖。
- 强制配置上行改为保存云端原配置；备份文件使用唯一文件名，避免同秒操作覆盖旧备份。

## 兼容与边界

- 数据库 schema 版本未调整，仅新增查询。原 Repository 的日常增删改接口保持不变。
- `DataExport.backupFormatVersion=2` 表示新格式；`algorithmStates=null` 标识缺少调度状态的旧备份。旧文件仍可读取，但无法补回其原本未保存的调度状态，界面会提示。
- 语录继续采用原有的“集合版本较高者优先”策略，未改变冲突解决规则。
- 数据库事务不等于数据库、文件系统和 WebDAV 之间的分布式事务：下行数据库提交后媒体下载若失败，会报告错误；已完成的数据库恢复不会撤销，媒体可以重试。
- SHA-1 在此用于与已有清单兼容的内容校验，不提供签名或可信来源认证。
- 网络验证使用 Ktor MockEngine，没有连接真实用户 WebDAV，也没有读取或修改用户应用数据库。
